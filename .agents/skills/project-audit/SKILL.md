# Project Audit

At the start of a work session, read [AGENTS.md](../../../AGENTS.md), [audit_protocol.md](../../../Other/audit_protocol.md), and the latest entries in [audit_log.md](../../../Other/audit_log.md).

## Follow the protocol

Read the team's protocol before analysis. Treat it as a draft until the team has reviewed and agreed to it. Explain sources, query logic, assumptions, and any limitations that help the team perform its checks.

If a meaningful human check introduces a useful practice not in the protocol, propose one short addition and get team approval before editing. Do not add a rule for every interaction.

## Maintain the audit log

The log records meaningful human checks of agent work: checking a source, verifying schema or calculations, challenging an assumption, correcting an interpretation, or confirming a claim. Skip routine approvals, wording feedback, the agent's own checks, and checks of human work.

Before adding an entry, read earlier entries, find the next unused number, and show the proposed category and wording. Add only after a team member approves. Use one of these categories: Caught an error, Verified a claim, Separated fact from opinion, Changed the analysis, or Improved the agent's instructions. Update the summary count. Make clear what the agent did and how the human checked it. Link a source or query when available.

Do not invent checks, results, dates, sources, or contributions from the second team member. If a human reports a check without evidence, say that the check was reported and mark any unresolved issue as pending. Preserve earlier entries and do not reuse numbers. If an issue is resolved later, add a dated resolution rather than erasing the earlier record.

## Scope

This skill does not authorize queries, spending, publishing, or unrelated repository changes.
